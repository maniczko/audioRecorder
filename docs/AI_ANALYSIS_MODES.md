# AI Analysis Modes

VoiceLog meeting analysis can return provider-generated output or a local fallback.
Every analysis payload should expose:

- `analysisSource`: `provider` or `fallback`
- `mode`: provider or fallback mode, for example `openai`, `anthropic`, `no-key`, or `fallback`
- `fallbackReason`: present for fallback output
- `generatedBy`: the system that produced the payload

## Provider Mode

Provider mode means the meeting analysis was generated by a configured AI provider.
Current provider values include:

- `openai` for server-side meeting analysis
- `anthropic` for explicit local demo builds that allow browser-side keys

Provider output should not include raw transcript text in audit logs, metrics, or Sentry context.

## Fallback Mode

Fallback mode means the app generated a safe local analysis or a degraded response instead of
provider output. The UI shows this as `Analiza lokalna`.

Fallback reasons:

- `no-key`: no AI provider key is configured.
- `disabled-feature-flag`: meeting analysis is disabled.
- `provider-error`: the provider request failed.
- `invalid-model-output`: the provider response could not be parsed or validated.
- `timeout`: the provider did not respond in time.
- `quota-rate-limit`: provider quota or rate limiting blocked the request.
- `empty-transcript`: there was no transcript content to analyze.

## Monitoring

The backend records fallback telemetry through `MetricsService.observeAiFallback`.
`MetricsService.getJsonSummary()` exposes:

- `aiFallbacks.total`
- `aiFallbacks.analysisTotal`
- `aiFallbacks.fallbackRate`
- `aiFallbacks.counts`
- `aiFallbacks.analysisCounts`
- `aiFallbacks.byWorkspace`
- `aiFallbacks.byEndpoint`
- `aiFallbacks.byReason`

The `/media/analyze` route also writes sanitized audit metadata:

- `mode`
- `analysisSource`
- `fallbackReason`
- `source`

Never include raw transcript text, prompts, provider keys, or bearer tokens in metrics, logs, audit
metadata, Sentry breadcrumbs, screenshots, or issue comments.
